P2G V2 当前评估报告
====================

项目名称
--------
P2G V2（长文 PDF 结构化理解与证据问答系统）

生成时间
--------
2026-08-12

目标
----
评估当前版本（相对 V2.14）在 PDF 结构识别、章节去噪、证据汇总与答案生成方面的实际效果，并形成可分享的进展说明。

一、整体结论
-------------
当前版本已经从"单纯把 PDF 切成块"进化为"能较好识别论文主干结构、过滤噪声标题/图注/附录提示词、在证据有限时保守作答"，两篇不同形态的论文（Agentopia 实验论文 25 节、Agent AI 综述 80 节）全流程实测均无幻觉、无英文泄漏、答案带可定位出处。

二、相比 V2.14 已解决的问题
----------------------------

1. 模型响应截断不再导致整段中断
   - 现象：附录密集章节的抽取 JSON 被输出预算截断，3 次重试全部失败，完整运行直接崩溃。
   - 修复：以 `finish_reason="length"` 判定截断；内容为空时关思考重新生成，有部分 JSON 时从该部分续写（续写尾部与部分内容拼接后解析、失败自动接力）；抽取输出预算 1800→4000 Token。之前崩在 "B. System Design Details" 的运行现在能跑完所有章节。

2. 全局问答答案质量
   - 局限类答案按句子保留证据，不再因一句无证据内容整条误杀。
   - "未来工作"问题只检索局限与结论章节，不再混入方法实现。
   - "矛盾"问题确定性列出跨章节冲突并附页码出处，不再答"证据不足"。
   - 提示词强制用自己的话概括、禁止粘贴原文引用；中文问题中文作答。

3. 英文原文不再泄漏进答案
   - 现象：抽取层约 18% 的事实 `statement` 直接照抄英文原文，答案模型原样写进答案。
   - 修复：抽取/章节归纳/总览/答案四层提示词统一要求英文证据先译后概；答案层加确定性英文兜底（连续 4+ 英文单词截断并移入 `unsupported_claims`，整段英文降级为"证据不足"）。

4. 指标类问题检索路由正确
   - 现象：配置表（Table 8）的每个数值行被标成 `kind="metric"`，在"评价指标"问题上压过真实指标定义（Q5 答出 "Table 8:"）。
   - 修复：检索打分对配置列名（Value/Setting/Parameter/…）和含配置标记的表格事实确定性罚分，相关表转储在指标类问题上降权。Q5 恢复为真实指标事实。

5. 矛盾检测从"偶然发现"升级为"确定性扫描"
   - 多行表头合并：Table 3 的 `Claude | Gemini` + `4.5-Opus | 3-Pro` 两行表头按列拼接，列身份不再丢失，64.28/36.02 这类"伪矛盾"从源头消失。
   - 文档级数值矛盾扫描：按（指标、行上下文、表标题）分组，只判"同一张表跨页冲突"为真矛盾，不同表同结构数值不再误报。Agentopia 误报从 29 个收敛到 0。

6. 结构去噪（换第二篇论文实测暴露的排版问题）
   - 目录类章节整节丢弃（Contents/Table of Contents/List of Figures/目录…，正文是页码表不是内容）。
   - 作者简介并入 back-matter。
   - 图片 OCR 文本（`<!-- Start of picture text -->` HTML 块）与 `<img>`/`<mark>` 标签建树前剥离。
   - 图注/提示词转储节点不再当章节：正文首行是 `Figure N:`/`Table N:` 且无编号签名、或正文首行是 `**Prompt:**` 等角色头、或裸标题是 `Output:`/`Input:` 等角色词的节点，正文并入父节点、子树提升。Figure 28 图注 "General Alpaca Training Framework" 不再被当 L2 章节吞掉 6.6.3 到附录 F 的整棵子树；综述章节数 83→80。
   - 章节层级归一化：用 `###`/`####` 表示主/子章节的论文，把"编号章节最小层级"整体平移到 L2。综述层级从 {L1:1, L3:14, L4:65} 归一到 {L1:1, L2:14, L3:65}。

7. 表格事实源头净化（V2.20）
   - 配置表数值行不再进入事实库（`_row_is_config_row`）：数值列名是通用标签（Value/Setting/Parameter/…）且表含配置标记或行上下文键全为通用标签时，该行在抽取源头就被跳过，不再以 `kind="metric"` 写进事实库和证据索引（此前 V2.18 只在检索打分时压掉）。真实结果表的通用列名（如 `Total`/`Mood`）在 `Model` 上下文下仍保留。
   - 碎片表头清洗（`_repair_header_name`）：pymupdf4llm 把宽表头拆成跨列碎片（`Reward (z-score)` → `Reward / (z-score / )`）再堆叠成 `(z-score Econ.`、`) Soc. (Δ)` 这类带悬空括号的噪声指标名；合并表头时对悬空开/闭括号做确定性清理。

8. 碎片章节合并（V2.21）
   - 小体积编号叶子子节不再各自触发一次抽取+归纳调用（`_merge_fragment_leaves`）：≤500 token、无子节点、编号签名带子号（`number:5.4`）的叶子节并入父节，子节标题保留为父节正文首行标记，小节号仍能锚定"小节级问题"的证据；主编号节（无子号）与字母前缀附录（如 `D.12`）不参与。合并需在 `_normalize_levels` 之前运行，避免层级重基准干扰合并判定。
   - Agentopia 实测：仅 `5.4 Computational Cost`（359 token）一处并入 `5. Experiments`，总 token 零丢失（+16 = 标记头），附录 `D.12 Computational Cost Details` 正确保留。

已验证基线（当前）：
- Agentopia（25 节含附录）完整运行：10/10 全局问答带可定位页码、零幻觉、零英文泄漏；"矛盾"问题 3 条可溯源矛盾（9 个事实、跨 6 页）；未来工作 4 条、局限 10 条。
- **V2.20 表事实净化复跑**（同一份 Agentopia PDF，缓存重跑约 16 分钟，本次仅 117 次 API 调用）：Table 8 配置行 22 条 `Value` 指标事实从源头清零；表头碎片噪声 `(z-score Econ.`/`e) Material`/`nt (z-scor Esteem`/`) Soc. (Δ)` 0 残留，替换为 `Econ.`/`e Material`/`nt Esteem`/`Soc. (Δ)`；10/10 问答依旧全部带页码出处，"评价指标"问题确认回答真实指标而非 "Table 8:"。
- Agent AI 综述（80 页、80 节）实测：10/10 问答真实出处、无幻觉；无数值表格时"矛盾"问题正确答"证据不足"。
- **V2.22 人工社会智能综述复跑**（`Artificial Social Intelligence: A Comparative and Holistic View` 中译版，新论文无缓存，本次 134 次 API 调用）：碎片合并处理了 `1.2 文章概述`（唯一 ≤500 token 的编号叶子节，源 markdown 层级较深故并入直接父节 `1.1`，标记保留、总 token 零丢失）；10/10 问答全部中文作答、9/10 带页码、零英文泄漏、Q10 正确答"证据不足"、executive_summary 连贯。该 PDF 标题结构较乱（1.2 层级深于 1.1、`4 讨论`被误嵌进`工作记忆`、`5 结论`被误嵌进`4 讨论`、期刊刊头 `CAAI` 被当章节），均为 #7 前后的预存问题，流水线仍产出全部有出处答案。
- **V2.21 碎片章节合并复跑**（同一份 Agentopia PDF，缓存重跑约 19 分钟，本次仅 114 次 API 调用）：`5.4 Computational Cost` 并入 `5. Experiments`、总 token 零丢失、子节标记保留；10/10 问答全部带页码、零英文泄漏，与 V2.20 相比 5 题完全一致，差异题均无事实回归（Q3 方法证据更全、Q9 未来工作不再混入局限、Q10 矛盾从 2 条升级为 3 条且更精确、Q6 数字一致仅措辞微调、Q8 覆盖略减为 LLM 采样差异）。
- 单元测试 99 个全部通过。

三、仍存在的问题
----------------

1. 附录提示词正文仍被抽取成低价值 "example" 事实（如 GPT-4V 游戏场景描述），token 浪费，与问答路由无冲突。
2. 图片 OCR 被整块剥离后，纯图表内的文字不再入事实库；综述实测问答未受影响，待用图表密集论文验证是否削弱"图表内容"类问题。
3. "未来工作"问题偶发仍混入方法实现描述，可再收紧事实 kind 白名单。
4. 高层摘要（`executive_summary`）是事实拼接式归纳，连贯性可提升。
5. 综述类论文子节碎片化：碎片合并已在 V2.21 实现（≤500 token 编号叶子节并入父节、子节标记保留），Agentopia 与人工社会智能综述两篇实测都只合并了 1 个碎片节、内容零丢失；但两篇都不是碎片化结构，调用数收敛的收益与对"小节级问题"定位精度的影响仍需真正有 60+ 单段编号子节的综述（如 Agent AI 综述原 PDF）实测。
6. 截断恢复率偏高：chunk_extract 381 次调用中约 26% 触发重生成/续写，机制正常但每次重新请求 API。

四、结论
--------
现阶段的版本已具备较好的"论文结构理解"能力（噪声去除、图注/附录去噪、层级归一化、碎片章节合并）与"可靠答案生成"能力（句子级证据审计、确定性矛盾扫描、中文转述 + 英文兜底），两篇不同形态论文实测零幻觉、零英文泄漏。V2.20 已把配置表噪声行与碎片表头从事实库源头清除，V2.21 已把碎片章节合并落地（Agentopia 复跑验证内容零丢失、10/10 问答无回归），V2.22 在第二篇（人工社会智能综述，标题结构较乱）上复跑验证：合并仍只处理符合条件的碎片节、内容零丢失，流水线在乱结构下仍产出 10/10 有出处的答案。剩余问题集中在效率与收尾：碎片合并的调用数收益仍需真正碎片化结构的综述实测、截断恢复率偏高、附录 example 事实 token 浪费，是下一步优化的重点方向。
